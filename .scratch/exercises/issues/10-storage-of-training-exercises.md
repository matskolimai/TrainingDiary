# 10: Storage of Training exercises

**What to build:** Trainings can be stored and read with their Training exercises and Sets, all or nothing. No
visible change; existing cases stay green. See `../spec.md` (Storage). Scaffolding: no new tests.

**Blocked by:** 01 (Modules and catalogue).

**Status:** done

- [ ] Tables `training_exercises(id, training_id FK ON DELETE CASCADE, exercise_id)` and `exercise_sets(id,
      training_exercise_id FK ON DELETE CASCADE, reps, weight_grams)`, autogenerated ids.
- [ ] Reads through a `@Relation` class; the mapper sorts children by id and maps `exercise_id` to an `Exercise` via
      `ExerciseCatalogue`.
- [ ] `@Transaction` DAO methods: insert a Training with its children; update a Training's name and replace its
      children; restore reinserts every row with its old id. Delete cascades.
- [ ] `Training` gains `exercises: List<TrainingExercise>`; repository: `addTraining(name, exercises)`,
      `updateTraining(training)`, `deleteTraining(id)`, `restoreTraining(training)`; callers pass the current
      (still empty) list.
- [ ] Database stays version 1; the committed schema JSON is overwritten; no `fallbackToDestructiveMigration`.
- [ ] The change summary reminds the user to clear the app's data once.
- [ ] `./gradlew check` and the device suite pass.
